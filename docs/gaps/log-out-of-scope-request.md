# (no route) vs `log-out-of-scope-request`

**Template:** `design-system/templates/log-out-of-scope-request/LogOutOfScopeRequest.dc.html` — titled "Log Referral": a single-column (840px) form with two cards — "How it came up" (Channel chips, Date, searchable Site combobox, and a "Link to a logged event" select that appears only for in-person referrals) and "Referred to" (four chips) — plus a sticky footer with a required-fields note, Cancel, and "Save referral". It records that a tenant asked for something outside the program's scope and where the worker pointed them. No free text, no tenant identifier.
**App:** No route, no component, no API route, no table. Verified by grepping `src/` for `referral`, `referred`, `out of scope`, `out_of_scope`, `outofscope`: zero hits in `src/db/schema/`, `src/app/api/`, or anywhere else under `src/`. The only hits in the repo are the design-system files themselves (`_ds_manifest.json`, `Dashboard.dc.html`, `LogDistribution.dc.html` — the "Outreach referral" distribution-type chip, `MonthlyReports.dc.html`, and this template). `src/db/schema/index.ts` exports ten tables (`activity_types`, `community_partners`, `events`, `program_goals`, `sites`, `supplies`, `users`, `site_supplies`, `supply_distributions`, `supply_distribution_items`); none stores a referral. The `request` grep in `src/app/api` only matches the `Request` type and `req.json()` — nothing domain-related.
**Data sources the app uses today:** none for this feature. Nearest analogues: `src/components/EventForm.tsx` (the `/events/new` form — same Popover + Command site combobox pattern, date input, `Card` grouping), `src/app/supply-distributions/components/SupplyDistributionForm.tsx` (a typed-category select), `src/lib/types/activity-feed.types.ts` + `src/db/schema/activity-feed.schema.ts` (the feed a saved referral would post to), and `src/app/dashboard/page.tsx` (the Quick Start card that would link here).

## C. Notes

- **This is a new feature, not a redesign.** There is no page to restyle. It needs a migration (new table under `src/db/schema/`, exported from `index.ts`), a `POST` route (and an options/list route), a page under `src/app/`, an `ActivityFeedService` method, a feed renderer, a dashboard link, and — for the monthly report — aggregation queries in `src/server/actions/reports.ts`. `docs/AUDIT.md` 5.3 already flags it as "defer, out of scope for the redesign".
- **Naming is inconsistent between folder and page.** The folder is `log-out-of-scope-request`, the `@template` name and h1 are "Log Referral", and the dashboard/monthly-report templates say "referral" / "Tenant Referrals". Use "referral" everywhere in code.
- **No free text and no tenant identifier — by design.** The "Referred to" subtitle says the details "stay between them and the referral". This matches the no-PII rule in `CLAUDE.md`; do not add a notes column to be helpful. The only consequence is that "Other" has no "please specify" field, so reporting on "Other" can never be broken down.
- **The event link is conditional but not cleared.** The template hides "Link to a logged event" when the channel is not "In person" but keeps `state.linkedEvent`. A build should clear `event_id` when the channel changes, or validate server-side that `event_id` is only stored with `channel = in_person`.
- **Site list source.** The template's `SITES` array is mock data. The `log-distribution` options route only lists sites with stock; a referral has nothing to do with stock, so the list should be all `sites` (as `GET /api/events/options` returns).
- **No list, detail, edit, or delete screen exists in the template set for referrals.** The only downstream views are the dashboard feed row and the monthly-report card. Decide whether workers can correct a mis-logged referral; every other record type has an admin table with edit/delete.
- **Visibility scoping.** Every existing list route restricts non-admins to their own rows (`eq(x.userId, currentUser.id)`); the monthly report does the same. A `referrals` list/aggregate should follow the same rule, which is why `user_id` is required.
- **Mock-only content:** the five site names, the three event options, the header name and initials, and today's date default.
- **App data the template dropped:** not applicable — there is no app data for this feature. The one existing datum the template ignores is `supply_distributions.distribution_type`, where the `log-distribution` template proposes an "Outreach referral" chip; if a referral is its own record, that distribution-type value is probably redundant and the two templates should be reconciled.
