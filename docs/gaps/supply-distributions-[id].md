# `/supply-distributions/[id]` (no app route) vs `distribution-detail`

**Template:** `design-system/templates/distribution-detail/DistributionDetail.dc.html` — a full-page, read-only distribution record: "Site — Date" title with Edit/Delete buttons, a Created/Updated line, a Profile-pattern card (Truck tile, Distribution Date, Site link, Type pill, "Total Items Distributed" breakdown, Distributed By avatar + name + role), then a "Distributed Items (N)" card with an Export CSV link and a line-items table whose footer shows the total.
**App:** **There is no `/supply-distributions/[id]` route.** `find src/app -path '*supply-distributions*' -name page.tsx` returns only `src/app/admin/supply-distributions/page.tsx` and `src/app/supply-distributions/new/page.tsx`. The closest live equivalent is the admin **dialog** `src/app/admin/supply-distributions/components/view-distribution-dialog.tsx`, opened from the Eye button in `distributions-table.tsx`. AUDIT 5.2 lists the promote-to-route decision as a step-10 item. Comparison below is template vs that dialog.
**Data sources the app uses today:** `GET /api/admin/supply-distributions/[id]/details` (`src/app/api/admin/supply-distributions/[id]/details/route.ts`) → `{ distribution, distributionItems[] }`. A second, richer `GET /api/admin/supply-distributions/[id]` (`[id]/route.ts`) exists and also returns `userEmail`, `eventDate`, and item `createdAt`, but nothing in the app calls its GET; only its `DELETE` is used. Tables: `supply_distributions`, `supply_distribution_items`, `supplies`, `sites`, `users`, `events`.

## C. Notes

- **A route/page is required.** Building this template means adding `src/app/supply-distributions/[id]/page.tsx` (or under `/admin/…`), choosing which API to call, and deciding access: `/[id]/details` and `/[id]` GET both allow any active user, while the list route hides other users' rows from non-admins. The page would expose any distribution by id to any signed-in user unless it applies the same ownership check. AUDIT 5.2 / 5.6 already defer this promotion to step 10.
- **Bug in the closest live equivalent.** `src/app/api/admin/supply-distributions/[id]/details/route.ts` selects `userName: users.firstName` and then returns `` userName: `${distribution.userName} ${users.lastName}` `` — `users.lastName` here is the Drizzle column object, so the dialog's "Distributed By" shows the first name followed by "[object Object]" (or similar). The sibling `src/app/api/admin/supply-distributions/[id]/route.ts` GET already does `CONCAT(first_name, ' ', last_name)` correctly and returns a superset of the fields (`userEmail`, `eventDate`, item `createdAt`). Unverified in a browser (no automation); read from the source. A route version should use or fix one of these.
- **Template drops app data that the dialog shows (list for the redesign decision):**
  - **Recipients** (`supply_distributions.recipient_notes`) — a NOT NULL column that the `POST` handler requires ("Site ID, recipient notes, and distribution items are required"). The manifest description says "recipients/notes in one card", but no `{{ recipientNotes }}` binding exists in the HTML. This looks like an omission, not a decision.
  - **Additional Notes** (`supply_distributions.notes`).
  - **Associated Event** (`events.title` via `eventTitle`, plus `eventId` for a link to `/events/[id]`).
  - **Total Cost** as a headline field (`supply_distributions.total_cost`); the template keeps it only in the table footer.
  - **Collapsible** items section (`itemsVisible` state) and the **Close** button.
  - The type value **`emergency_distribution`** (no pill).
- **Label mismatch for `event_distribution`:** this template says "Community Event" (with a `Calendar` icon); `distribution-management` says "Event Distribution"; the app's `formatDistributionType()` produces "Event Distribution". Pick one.
- **Mock-only content:** site "Byrne Creek", worker "Trevonne Garamukanwa", role "Tenant Engagement Worker", both timestamps "Jun 3, 2026, 7:16 AM", the two items ("Cooling Kit" 17 × $10, "Bottled Water (Case)" 12 × $4.50), header initials "JM" / "Joseph Masongsong". `totalCostLabel` is computed but not bound; `onEdit` is a no-op; `onDelete` is a `window.confirm` with an empty body.
- **Unit cost source.** The template's `unitCost` is per item; the app stores a snapshot in `supply_distribution_items.unit_cost_at_time` (not the live `supplies.cost_per_unit`), which is the correct value to show on a historical record.
