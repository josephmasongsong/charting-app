# /admin/sites/new (+ /admin/sites/[id]/edit) vs `create-site`

**Template:** `design-system/templates/create-site/CreateSite.dc.html` — create-only intake: blue `AppHeader`; breadcrumb "Dashboard / Sites / Create site"; four icon-tile cards (Site identity · Address and location with a "Find on map" geocode step and map preview · Site properties as toggle tiles · Starting supplies with live main-inventory math); a sticky bottom action bar with a ready note and a Save disabled until complete; a sticky 320px "Required fields" checklist rail.
**App:** `SiteForm.tsx` (client, 860 lines) rendered by `/admin/sites/new` (`mode="create"`) and `/admin/sites/[id]/edit` (`mode="edit"`, prefilled from `GET /api/admin/sites/[id]`). Client-side Zod (`createSiteSchema` in `src/lib/validations/sites.ts`) then `POST /api/admin/sites` / `PATCH /api/admin/sites/[id]` with `newSupplies` / `existingSupplies` / `removedSupplies`; options from `GET /api/admin/sites/options` (`users {id,name,email}`, `communityPartners {id,name}`, `supplies {id,name,costPerUnit,quantity}`).
**Data sources:** `sites` columns `name, latitude, longitude, address, number_of_tenants, has_community_room, has_community_partner, community_partner_id, is_single_senior_only, user_id`; `site_supplies` rows. `sites` has **no region, postal, or draft/status column**, and every column except `community_partner_id` is `notNull`.

**The inventory-direction conflict (settle before any wiring).** Template: "Optional — moves stock **from** main inventory to this site", with "N will remain" math and an over-stock block. App and API: "Quantities will be **added to both** site inventory and main supply counts" — `POST /api/admin/sites` runs `supplies.quantity = supplies.quantity + input` (verified, `route.ts` ~L308), and PATCH/DELETE are consistent (removal subtracts). Today `supplies.quantity` is a system-wide total including site stock, not a warehouse balance. Adopting the template's math flips the sign in three routes and re-interprets existing data — a data-model decision for `DEFERRED.md`, not a redesign. Until it is made, the template's stock notes and over-stock blocking must not be wired (they would show wrong numbers), and the app's "added to both" subtitle stays.

Behaviour to keep: the `formData`/`siteSupplies`/`existingSupplies`/`removedSupplies` state, client `safeParse` + per-field errors + server `details` mapping, the URL/method branch, the success message and 2s redirect to `/admin/sites`, `router.back()` on Cancel, the options and edit-prefill fetches, `getAvailableSupplies` (hides already-chosen supplies), the supply quantity `> 0` checks, the edit-mode Current Inventory block, and both loading states.
