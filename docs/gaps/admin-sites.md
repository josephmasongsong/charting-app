# /admin/sites vs `site-management`

**Template:** `design-system/templates/site-management/SiteManagement.dc.html` — page header + "Add Site" primary button; an optional four-stat row (`showStats`); one card containing a search row, a dense sortable teal-header table (Name · Address · Assigned Worker · Community Room · Community Partner · Senior Only · Actions) with zebra striping, and a First / Previous / 1 2 3 … N / Next / Last pager with a "Showing X to Y of N results" label.
**App:** `/admin/sites` → `src/app/admin/sites/page.tsx` (client) → `SitesTable.tsx` (client fetch, sort, pager, messages) → `DeleteSiteDialog.tsx`, `BooleanBadge.tsx`. API `GET /api/admin/sites?page&limit=10&search&sortBy&sortOrder` (`sites ⋈ users ⋈ community_partners` → `{ sites, pagination }`; search `ilike`s name, address, worker name, partner name), `DELETE /api/admin/sites/[id]` (returns each `site_supplies.quantity` to `supplies.quantity` before deleting). Wrapped by `admin/layout.tsx` (`requireAdmin`, `p-6`/`max-w-7xl`) — the page adds `container mx-auto p-4`, so padding is doubled today.
**Data sources:** the GET above; the delete route; nothing else.

**Pattern-setter notes (this table is the reference for the six other admin tables — program-goals, activity-types, supplies, distributions, users, community-partners, per `AUDIT.md` §5.5):**

- **Density.** Native `<table>`, `min-width:1080px` inside `overflow-x:auto`, 14px body text, header cells `10px 14px` padding, body cells `9px 14px` — tighter than shadcn's `TableCell p-2` + `text-sm` with taller line boxes. Header: `--surface-chrome` fill, white 12px uppercase `.04em`, `1px #0a7276` cell borders (`#0a7276` is a DS literal, not a token). Body cells each carry a `1px --bch-gray-200` border — full grid lines, not just row dividers. This is the readme's "government-software density" and matches `ui/data-table`'s header/cell treatment, but `DataTable` (props-driven, no sort/pagination) cannot host this table — the conversion styles `ui/table` primitives (or extends `DataTable`), and whichever is chosen becomes the admin-table idiom.
- **Zebra + hover.** `tbody tr:nth-child(even)` → `--surface-muted`; hover → `--action-selected` (selection blue, consistent with the DS "blue = interaction" rule). shadcn's default is hover `bg-muted/50`, no zebra.
- **Pagination.** Always visible (even at one page), left label "Showing X to Y of N results", right buttons First · Previous · numbered pages · … · last-page number · Next · Last; buttons are white with `--border-default`, action-blue text, `--radius-control`, hover `--action-selected`; the active page is filled `--action-primary`; disabled buttons keep full opacity with `--bch-gray-500` text and `cursor:not-allowed`. **Keep the app's sliding current±2 window** rather than the template's fixed 1–3+last window, which loses the current page past page 3; keep the app's `hidden sm:inline` responsive labels. The app's one-page "Showing all N results" line collapses into the always-visible footer.

Behaviour to keep: submit-only search (`handleSearch`), `sortConfig` + `handleSort('name')`, `fetchSites(page, search, sort)` and its error path, the 5-second auto-clearing message/error `Alert`s, `openDeleteSite` → `DeleteSiteDialog` (fetch DELETE, success/error callbacks, refresh), the `Eye`/`Edit` navigation targets (`/sites/[id]`, `/admin/sites/[id]/edit`), the two-state empty copy with "Clear search", and the default sort `createdAt desc` unless the sort decision below is made.
