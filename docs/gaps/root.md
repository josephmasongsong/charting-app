# / vs the converted `/login` (no template)

**Template:** none. `docs/AUDIT.md` §5.4 says to extrapolate `/` from `sign-in`; the reference here is the converted sign-in page itself, `src/app/login/page.tsx` (commit `50a0e99`), not the `.dc.html`.
**App:** `/` → `src/app/page.tsx`. Server component: `getServerSession(authOptions)`; `redirect('/dashboard')` when a session exists; otherwise a "Welcome" card with two full-width buttons that link to `/login` and `/forgot-password`.
**Data sources:** the session only. No fetch, no state, no form.

The behaviour to keep is exactly: the server-side session check and `redirect('/dashboard')`, the two links and their targets, and the fact that this is a server component (no `'use client'`, no hooks).
