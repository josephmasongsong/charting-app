# /events vs `events`

**Template:** `design-system/templates/events/Events.dc.html` — teal `AppHeader`; title "Events" + a summary sentence; "+ Add event" primary button; a one-row filter strip (search, Site, Activity type, Date range); then **one card** holding a grouped **row list** (not a table): a teal header band per group ("MAY 2026" · "9 events"), rows with a 52px DOW/day tile, title link, muted meta line (organizer · site · participants), and three bare icon actions (Edit, Duplicate, Delete); footer "Showing 1 to 12 of 40 events" + outline "Load 12 more".
**App:** `/events` → `src/app/events/page.tsx` (server: `getEvents()` Drizzle query over `events ⋈ users ⋈ sites ⋈ activity_types`, 10 per page ordered `event_date desc, created_at desc`, plus a filtered `count(*)`; `getFilterOptions()`; `redirect('/login')`; `isAdmin`) → `src/app/events/components/EventsListClient.tsx` (client: URL-synced filters via `router.push`, one `Card` per event, numbered pagination) → `DuplicateEventDialog` → `POST /api/events/[id]/duplicate`.
**Data sources:** the query above; filter options from `activity_types`, `sites`, and `users` that have events; search params `search`, `activityType`, `site`, `organizer`, `page`.

**Rows: cards or table?** The template presents rows as **list rows inside a single bordered card** — no `<table>`, no column headers, no per-row card chrome. That is a different component from the app's `grid grid-cols-1 gap-3` of `Card`s: the row markup, the wrapper, and the grouping logic all change, while the filter/URL state machine stays. `ui/data-table` is *not* the right primitive (it is a header-driven `<table>`); the closest ported patterns are the DS `StaffRow`-style grid row and the `ActivityFeed` divider-row list. Expect `EventsListClient.tsx` to be rewritten in its render section end to end, with `updateURL` / handlers / `formatDate` untouched.

Behaviour to keep: all five URL-synced filters and `clearFilters`, `router.push('/events?…')` on every change, the 10-per-page numbered pagination (`Math.min(totalPages, 7)` window), the `isAdmin` gating of Edit/Delete, `DuplicateEventDialog` and its post-duplicate redirect, the "No events found" empty state with "Clear all filters", `formatDate`'s `en-US` output, and `generateMetadata`.
